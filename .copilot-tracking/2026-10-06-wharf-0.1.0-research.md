# Wharf 0.1.0 research

## Scope and decisions already settled

- The repository was renamed to `bartr/wharf`; the permanent Go module path is
  `github.com/bartr/wharf`.
- The supported toolchain is Go 1.27. The installed toolchain is Go 1.27.0.
- The user asked this session to stop after a local commit on `v0.1.0`; push,
  merge, and tag creation are excluded.
- Session 1 is foundation-only. Manifest parsing, Docker integration, host
  checks, state, Harbor, Copilot execution, and operational command behavior
  are explicitly deferred (`wharf-sessions.md:49-53`).

## Evidence

### Repository and requirements

- The repository currently has no root Go module or root production Go
  packages. Existing Go modules are isolated smoke fixtures under
  `smoke-tasks/`, so a root module introduces no package collision.
- Go entry points must use the standard `cmd` structure and reusable code must
  stay outside `cmd` (`wharf.jsonl:31-32`).
- The version must exist in exactly one package-level string variable, all
  consumers must use it, and release builds must override that same variable
  through `-ldflags -X` (`wharf.jsonl:33-38`).
- The stable v1 command surface is `check`, `smoke`, `run`, `resume`, `status`,
  `stop`, `report`, `completion`, and `version` (`wharf.jsonl:206-215`).
- Help must support `--help` and `-h`; version output must contain only the
  effective semver; Bash and Zsh completion are required
  (`wharf.jsonl:40-43`).
- Unknown commands and flags must fail explicitly, and stable exit categories
  must cover success, invalid input, unsupported host, blocked run, partial
  run, and internal failure (`wharf.jsonl:217-219`).
- Configuration precedence is flag, environment, manifest, then built-in
  default (`wharf.jsonl:218`). Session 1 owns only global logging settings, so
  it must prove flag-over-environment-over-default while leaving the manifest
  layer for session 2.
- Console output is tab-delimited human presentation; durable logs are
  independent structured JSON; quiet mode must not suppress durable evidence;
  secrets must be redacted (`wharf-prd.md:231-242`).
- Repeatable verbosity through `-vvv` is required (`wharf.jsonl:275`).
- The repository must document the Go toolchain and expose one validation
  command that formats, validates, tests, and builds (`wharf.jsonl:357-358`).
- Secret redaction needs a synthetic-credential test
  (`wharf.jsonl:362`).

### Library behavior

- Cobra supplies command parsing, command-specific help, unknown-input
  rejection, and Bash/Zsh completion generation. Its official completion guide
  documents `completion bash` and `completion zsh`.
- Cobra uses pflag, whose count flag is the direct representation for repeated
  verbosity shorthand such as `-v`, `-vv`, and `-vvv`; no argument rewriting is
  needed.
- Cobra persistent flags are inherited by subcommands, which fits the global
  logging options. Explicit reads from the command flags avoid Viper and keep
  precedence observable.
- `log/slog` provides handlers, custom levels, `ReplaceAttr`, and native
  line-delimited JSON. A Wharf-owned interface can keep callers independent of
  `slog` and carry typed secret metadata before conversion.

## Alternatives considered

### Nested `wharf/` Go module

Rejected. It would add `wharf/cmd/wharf`, complicate root release automation,
and separate the product from its now-renamed repository without providing a
real isolation benefit.

### Public `pkg/` tree

Rejected for 0.1.0. Wharf has no committed public Go API. `internal/` prevents
accidental external dependencies while package contracts are still evolving.

### Viper or implicit environment binding

Rejected. Implicit binding obscures whether a value came from a flag,
environment variable, or default and makes precedence tests less direct.

### Cobra-generated global command variables

Rejected. Constructors returning fresh commands avoid test leakage between
executions and permit explicit dependency injection for streams, environment,
version, and logging.

## Recommended approach

Use one root module and these responsibility-based packages:

```text
cmd/wharf/main.go          thin process entry point
internal/command/          Cobra construction, global flags, subcommands
internal/config/           typed global settings and explicit environment reads
internal/logging/          Wharf logger interface, console/JSON sinks, redaction
internal/version/          sole Version variable
internal/exitcode/         typed categories and process-boundary mapping
```

Keep golden fixtures in package-local `testdata/` directories. Do not add
`pkg`, `common`, or `utils`.

Use these explicit global environment variables:

- `WHARF_LOG_FORMAT` with `text` and `json`
- `WHARF_QUIET` as a strict boolean
- `WHARF_VERBOSE` as an integer from 0 through 3

Use defaults of text console output, non-quiet operation, and verbosity 0.
Reject malformed environment values and cap flag verbosity at 3. Flags override
environment values only when Cobra reports that the flag was changed.

Define stable exit values:

- `0`: success
- `1`: internal failure, including intentionally unimplemented 0.1.0 commands
- `2`: invalid input
- `3`: unsupported host
- `4`: blocked run
- `5`: partial run

Construct the root command without automatic error or usage printing. The
single process boundary prints one concise error to stderr and returns the
mapped code. Parse/usage errors become invalid input; typed application errors
retain their category.

Define `Version = "0.1.0"` only in `internal/version`, making the linker target:

```text
github.com/bartr/wharf/internal/version.Version
```

Implement a Wharf logger interface with typed attributes, including an explicit
secret constructor. Apply a configurable redaction hook before dispatching to
both sinks. The console sink is either a tab-delimited human handler or a JSON
handler; quiet mode disables nonessential console records only. The durable
sink always emits versioned JSON and remains active in quiet mode.

Use Cobra's built-in Bash and Zsh generators behind an explicit
`completion [bash|zsh]` command. Operational commands return a typed,
plain-language not-implemented error and never return success.

## Risks

- Cobra/pflag help defaults can change across dependency upgrades. Pin the
  dependency and golden-test root and subcommand help.
- Logger fan-out must clone records before handlers inspect attributes to avoid
  mutable-record surprises.
- Tests must use fresh command instances; package globals would leak changed
  flags and output buffers.
- Version integration tests must target the exact sole variable or they can
  falsely pass while release builds remain broken.

## Explicitly not taken

- Manifest configuration or `--dry-run` behavior; session 2 owns both.
- Real behavior for any operational command.
- Durable run-log files or event schemas; only the reusable always-JSON logger
  API is established.
- Docker, host inspection, task discovery, state, scheduling, or agent code.
- Public Go API commitments.
